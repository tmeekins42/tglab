  depths and the controls do not currently know.
- exposure does not visibly stretch the histogram. Suspected to be the SDR
  display window rather than the data: values pushed above 1.0 leave the visible
  range instead of stretching it. Related: showing where the SDR window sits
  within the full range, which Tim suggested as a way to make headroom legible.
  if the histogram shows the entire image, and what is displayed, can we show a window around the displayed area?
- proxy resolution for interactive edits: work at view resolution while a slider
  moves, full resolution when idle. Benched deliberately -- local-neighbourhood
  algorithms give different results at lower resolution, so a proxy is only
  honest for the preview.
- threshold_otsu / _triangle / _isodata have no GPU path, and deriving a level
  from a histogram is why. With BuildHistogram they become build-on-GPU, read
  4 KB, compute the level, dispatch the existing threshold kernel. Two things to
  settle first: whether Otsu on the subsampled histogram picks the same level as
  Otsu on every pixel, and that such a stage cannot batch with its neighbours.
  (This is the same ground as "add GPU implementation for local_threshold".)

DONE (recent, pruned periodically)
- brightness: handled only RGBA8 and R32F and silently produced ZEROS on
  anything else -- a demosaiced raw came out black with no error. Now goes
  through PixelBuffer like every other algorithm, so all four formats work.
- brightness sliders renamed: amount -> brightness, gain unchanged.
- PixelBuffer's `default: // RGBA8` in Unpack and PackInto now name every format
  explicitly and complain about an unknown one. That switch sits behind thirteen
  algorithms, so it was the single place a new format would be misread by all of
  them at once.
  NOTE: gaussian_blur, median_blur and sobel were checked and are fine -- they
  branch on format to pick a STRATEGY (single- vs multi-channel), not to decide
  whether to do anything, and the paths that matter go through PixelBuffer.
  Measured on an RGBA16F input: only brightness was broken.
- when a script's viewers are first docked, the LAST display() is now selected
  rather than whatever tab the saved layout had on top. ImGui persists the
  selected tab per dock node in tglab_layout.ini, so hello.tgl kept showing
  "original" and the brightness slider appeared to do nothing -- the visible tab
  was the source image. A tab the user has since chosen is left alone: selection
  only happens on the frame a viewer is first docked.
- grayscale bailed out on anything but RGBA8 (`if (format != RGBA8) return;`),
  leaving its output as allocated -- i.e. BLACK. It is the first stage in
  hello.tgl, so everything downstream went black too and it read as a broken
  brightness slider. Found by Tim, who correctly suspected grayscale rather than
  brightness.
  A registry-wide sweep then found three more, all the same shape: sobel,
  hysteresis and gaussian_blur read half- and 32-bit-float images as BYTES --
  not zeros but plausible-looking nonsense, which is harder to notice. All four
  now handle every format.
  My earlier grep-based survey missed every one of these; only enumerating the
  registry and running each algorithm on each format found them. That sweep is
  now a test.
  STILL OPEN, deliberately: threshold and threshold_bernsen output black on a
  float image because their `level` is fixed at 0..255 while the values are
  0..1. That is the same "ranges do not follow the format" issue as
  basic_adjust's, not a "did not run" bug.
- GPU kernels for brightness and grayscale. At 21 MP, chained as hello.tgl runs
  them: 1854 ms -> 209 ms. Note the units differ between the paths on purpose --
  brightness's offset is scaled by 255 on the CPU (which works in the source's
  units) and NOT in the shader (a UNORM SRV already gives 0..1). Only the
  CPU/GPU agreement test would catch getting that wrong.
  Three tests had used grayscale/sobel as their "CPU-only algorithm" example and
  broke once those gained kernels; they now use guided_filter, which is
  genuinely CPU-only rather than merely not-ported-yet.
- thresholds.tgl now ships with assets/page.png -- a synthetic scan, text under
  a lighting gradient -- rather than pointing at test.png. The algorithms were
  correct all along: test.png is a smooth gradient with a checkerboard patch,
  local stddev 3-11 across it against 127 in the patch, so every local method
  correctly returned nearly uniform white with all its black pixels confined to
  the corner. Correct output, useless demonstration.
- the info-panel histogram now follows a tab switch. It is measured during a
  pipeline RUN, and switching tabs is not one, so a viewer never shown during a
  run had no histogram and the panel kept displaying the previous tab's. Asking
  for a new subject now requests a run; the stage cache makes it nearly free
  since nothing recomputes.
- gaussian_blur and box_blur are separable on the GPU now, in two passes, so
  their sigma/radius ceilings are gone. They used to fall back to the CPU above
  sigma 4 / radius 24 -- exactly where a blur costs most. At sigma 12 the GPU
  time barely moves (22 -> 25 ms) while the CPU goes 111 -> 701 ms.
  The remaining ceilings (bilateral, kuwahara, symmetric_nearest) are real:
  those weights do not separate.
